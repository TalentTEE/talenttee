## 3. 더미 데이터 전략

**핵심 원칙**: 백엔드 API 스펙에 맞춰 더미 데이터를 준비하고, API가 준비되면 fetch로 교체만 하면 되도록 구조화.

```typescript
// lib/api.ts — 모든 API 호출을 한 곳에 집중

const USE_DUMMY = process.env.NEXT_PUBLIC_USE_DUMMY === 'true';

export async function getResume(id: string): Promise<ResumeProfile> {
  if (USE_DUMMY) return DUMMY_RESUME;
  return fetch(`/api/resume/${id}`).then(r => r.json());
}

export async function getMatchResults(seekerId: string): Promise<MatchResult[]> {
  if (USE_DUMMY) return DUMMY_MATCHES;
  return fetch(`/api/match/seeker/${seekerId}`).then(r => r.json());
}

// ... 모든 API에 동일 패턴
```

### 더미 데이터 파일

```
frontend/src/lib/dummy/
├── user.ts              → Alice(구직자), Bob(채용담당자) 프로필
├── resume.ts            → 완성된 이력서 + 시장가치
├── datasources.ts       → 연결된 데이터소스 목록
├── jobs.ts              → 채용공고 3개
├── matches.ts           → 매칭 결과 Top-5 (기본 정보)
├── profile-report.ts    → 상세 프로필 리포트 (에이전트 분석 결과)
├── negotiation.ts       → 협상 세션 + 5라운드 데이터
├── agreement.ts         → 합의 결과 + 온체인 기록
└── escrow.ts            → 에스크로 잔액 + 결제 내역
```

## 4. 페이지별 상세

### 4-1. 로그인 페이지 (`/`)

```
[NEAR 지갑으로 로그인] 버튼
  → near-connect로 지갑 연결
  → POST /auth/near/challenge → 서명 요청
  → POST /auth/near/verify → JWT 수신
  → role에 따라 대시보드로 이동
    - SEEKER → /dashboard/seeker
    - EMPLOYER → /dashboard/employer

더미: 지갑 연결 없이 Alice/Bob 선택 → 바로 대시보드
```

### 4-2. 구직자 대시보드 (`/dashboard/seeker`)

```
┌─────────────────────────────────────────┐
│  구직 활동  [OFF ─── ⬤ ON]               │
│  "AI가 자동으로 매칭하고 협상을 진행합니다"   │
├─────────────────────────────────────────┤
│  데이터소스 연결 상태                      │
│  [GitHub ✓] [Slack ✓] [Discord ✓] [정부24 ✓] │
│  [+ 데이터소스 추가]                       │
├─────────────────────────────────────────┤
│  내 이력서                                │
│  상태: 완성 ✓                             │
│  기술: TypeScript, React, NestJS, ...    │
│  경력: 3년 (프론트엔드/백엔드)              │
│  [이력서 상세 보기]  [이력서 재생성]          │
├─────────────────────────────────────────┤
│  시장가치                                 │
│  적정 연봉: 6,000만 ~ 7,500만원            │
│  강점: TypeScript 풀스택, 오픈소스 기여      │
│  [상세 분석 보기]                           │
├─────────────────────────────────────────┤
│  진행 중인 협상                             │
│  Company A - 87% 매칭 - Round 3/7  [모니터링] │
│  Company B - 85% 매칭 - 합의 완료 ✓ [결과 보기] │
└─────────────────────────────────────────┘
```

> **구직 활동 토글**: ON 시 프로필이 매칭 풀에 등록되며, 매칭 → 협상이 별도 동의 없이 자동으로 이어짐.
> 사용자 개입 지점은 협상 중 "개입 입력"과 최종 "합의 승인/거절"뿐.

### 4-3. 채용담당자 대시보드 (`/dashboard/employer`)

```
┌─────────────────────────────────────────┐
│  에스크로 잔액: 5.0 NEAR                   │
│  [추가 예치]                               │
├─────────────────────────────────────────┤
│  내 채용공고                               │
│  1. 백엔드 개발자 (ACTIVE)                  │
│     최대 협상 인원: 3명  [수정] [마감]        │
│  [+ 새 공고 작성]                           │
├─────────────────────────────────────────┤
│  진행 중인 협상                             │
│  Alice - 87% 매칭 - Round 3/7  [모니터링]   │
│  Charlie - 82% 매칭 - Round 1/7  [모니터링] │
└─────────────────────────────────────────┘
```

> **협상 자동 진행 플로우**: 매칭 순위 상위 후보자가 "최대 협상 인원" 수만큼 자동으로 협상 테이블에 진입.
> 협상 시 실제 이력 정보 열람 비용이 에스크로 크레딧에서 자동 결제됨 (NEAR 프로토콜 자동결제).
> 별도의 [동의/거절] 없이 크레딧 잔액 내에서 자동 진행.

### 4-10. 협상 히스토리 (`/negotiation/:sessionId/history`)

```
ECDH 복호화 (클라이언트 사이드):
  1. near-connect에서 사용자 개인키 접근
  2. tweetnacl로 Ed25519 → Curve25519 변환
  3. 상대방 공개키 + 내 개인키 → ECDH → session_key
  4. 각 라운드 encrypted_data 복호화
  5. 복호화된 전체 라운드 표시

승연과 협의 필요: 복호화 로직 공유
```
